## 三、环境搭建（Windows）

> 按您的偏好：**虚拟环境安装在 D 盘**，不占用 C 盘空间。只需做一次。

### 1. 创建 D 盘虚拟环境（已创建可跳过）

```powershell
python -m venv D:\yinlingban_env
```

### 2. 安装依赖（核心依赖很小，安装很快）

```powershell
cd "C:\Users\Administrator\Desktop\新建文件夹\backend"
D:\yinlingban_env\Scripts\pip.exe install -r requirements.txt
```

### 3. 创建配置文件

```powershell
copy .env.example .env
```

`.env` 留空也能正常启动（全部自动降级本地模式），需要云端大模型时再填 Key。

### 环境要求

- Python 3.10 及以上（当前开发环境 3.14）
- 无需安装 PostgreSQL / Redis / Milvus（默认 SQLite + 内存缓存 + 本地向量库）
- 天气功能需要能访问外网（open-meteo.com，免费无 Key）

## 四、启动与停止

### 启动（一键）

**双击项目根目录的「银龄伴.py」**（`yinlingban_env\银龄伴.py`，或直接运行 `backend\start.py`）：
自动启动服务 → 浏览器自动弹出测试页 → 直接用，无需任何其他操作。

- **文字理解走 DeepSeek 云端**：启动时检查 `backend/.env` 里的 `DEEPSEEK_API_KEY`，未配置会给出中文提示（不会再自动安装/拉起本地模型）
- 服务已在运行时再双击 → 不重复启动，直接开浏览器
- 用错 Python → 自动切换 D 盘虚拟环境
- 端口被占 → 自动换端口并提示新地址
- 出错 → 窗口停住显示中文原因，不闪退

命令行方式（效果相同）：

```powershell
cd "C:\Users\Administrator\Desktop\新建文件夹\backend"
D:\yinlingban_env\Scripts\python.exe start.py
```

可选参数：

| 参数 | 说明 |
|---|---|
| `--port 8080` | 换端口（默认 8000） |
| `--host 127.0.0.1` | 只允许本机访问（默认 0.0.0.0 局域网可连，方便前端联调） |
| `--reload` | 开发模式：改代码自动重启 |

### 启动成功后可访问

| 地址 | 用途 |
|---|---|
| `http://localhost:8000/` | **联调测试页**（一键启动会自动打开） |
| `http://localhost:8000/docs` | Swagger 接口文档（可在线调试所有接口） |
| `http://localhost:8000/health` | 健康检查（查看当前模型/向量库/缓存状态） |

关闭黑窗口，或选中窗口按 `Ctrl + C`。

## 五、AI 模型配置

**文字理解统一走 DeepSeek 外部 API**（V8 起已彻底移除本地大模型 Ollama 与内置本地回复引擎）。

### 模式：DeepSeek 云端（唯一模式，对话质量最佳）

在 `backend/.env` 中填写：

```ini
LLM_PROVIDER=deepseek
DEEPSEEK_API_KEY=sk-你的key
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-v4-flash
```

- 模型默认 **DeepSeek-V4-Flash 正式版**（`deepseek-v4-flash`，快而省，官方 2026-07-31 正式版）；想要更强可改成 `deepseek-v4-pro`。
- Key 申请：https://platform.deepseek.com （新用户有免费额度）

> 未填 Key 时小伴会在聊天里用中文提示配置步骤；**不会**再退回任何本地引擎。
>
> **也可以完全不用碰文件**：在测试页右上角点「⚙️ 密钥设置」→ 填 Key（模型名与请求地址已自动填好 `deepseek-v4-flash` + `https://api.deepseek.com`）→ 点「测试连接」或直接保存，保存时自动做一次联通测试：连通才启用，失败会给出中文报错原因（如 401 Key 无效 / 429 太频繁 / 超时等）。

### 切换/查看模型

改完 `.env` 重启 `start.py` 即生效；或在测试页「⚙️ 密钥设置」里直接改模型名并保存（热生效，不用重启）。当前生效的模型可随时通过 `GET /api/model` 或测试页顶部状态栏查看（启动/刷新页面时会自动做一次联通测试）。

### 系统类

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/health` | 健康检查（含各组件状态） |
| GET | `/api/model` | 当前生效的 AI 模型与 ASR 模式 |

### 对话类

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/chat` | **核心对话接口**（见下方返回字段说明） |
| POST | `/api/asr` | 语音识别（上传音频文件，需配置 ASR） |

**POST /api/chat 请求体：**

```json
{
  "user_id": 1,
  "text": "我有高血压，平时吃东西要注意什么",
  "session_id": 1
}
```

**返回（前端联调重点字段）：**

```json
{
  "session_id": 1,
  "reply": "这个问题问得好，我给您讲讲。高血压要少吃盐……",
  "emotion": "平静",
  "expression": "认真",
  "action": "讲解手势",
  "sources": [
    {"title": "高血压老人日常管理要点（国家卫健委…）", "category": "慢病管理", "score": 0.42}
  ],
  "tool_info": null,
  "elapsed_ms": 35.2
}
```

字段说明（对应产品文档 4.2 数字人交互设计）：

| 字段 | 取值 | 前端用途 |
|---|---|---|
| `emotion` | 开心 / 难过 / 焦虑 / 生气 / 平静 | 老人情绪（对应情绪表情映射表） |
| `expression` | 开心 / 关切 / 耐心 / 认真 / 鼓励 | 驱动数字人表情 |
| `action` | 打招呼 / 倾听 / 讲解手势 / 提醒 / 安抚 / 告别 | 驱动数字人动作 |
| `sources` | 知识来源数组 | 健康回答标注来源（可追溯） |
| `tool_info` | 提醒/天气/社区调用结果 | 卡片化展示工具结果 |

## 七、WebSocket 对接协议（给角色1赵华）

> 前端工程师重点阅读本节。协议已通过测试页（templates/index.html）完整验证，可直接参考其实现。

### 连接与握手

```
连接地址：ws://localhost:8000/ws
连接成功后必须先发：
{"type": "hello", "user_id": 1}
服务端返回：
{"type": "connected", "user_id": 1, "message": "小伴已上线，随时跟我聊天"}
```

### 客户端 → 服务端（4 种消息）

```jsonc
// ① 文字对话（前端用浏览器 Web Speech API 识别语音后传文字）
{"type": "chat", "user_id": 1, "session_id": 1, "text": "今天天气怎么样"}

// ② 语音打断（检测到用户说话时发送，立即停止当前播报）
{"type": "interrupt"}

// ③ 语音帧（可选，配置了后端 ASR 时用）
{"type": "chat_audio", "audio": "<base64编码的音频>"}

// ④ 心跳
{"type": "ping"}
```

### 服务端 → 客户端（事件流，一轮对话的完整时序）

```
① {"type": "session",     "session_id": 1}                      ← 会话建立
② {"type": "emotion",     "emotion": "难过", "expression": "关切"} ← 表情先行（语音前切换！）
③ {"type": "tool_start",  "tool": "query_weather"}               ← 工具开始执行（可显示加载动画）
④ {"type": "reply_delta", "text": "今天"}                         ← 流式文本（多次，逐字/逐词）
⑤ {"type": "reply_delta", "text": "天气不错……"}
⑥ {"type": "reply_done",  "reply": "全文", "expression": "认真",
    "action": "讲解手势", "sources": [...], "tool_info": {...}}   ← 本轮完成
```

**关键时序要求（对应任务 2.13）**：`emotion` 事件在 `reply_delta` 之前到达，前端应先切换数字人表情，再开始 TTS 播报，实现"表情在语音开始前切换"。

### 服务端主动推送（到点提醒，数字人主动播报）

```json
{
  "type": "reminder_due",
  "reminder_id": 5,
  "content": "吃降压药",
  "message": "到时间啦！别忘了：吃降压药。",
  "expression": "认真",
  "action": "提醒"
}
```

前端收到后：切换数字人表情 → TTS 播报 `message` → 字幕显示。

### 错误事件

```json
{"type": "error", "message": "大模型响应超时", "solution": "请稍后重试；或调大 .env 中 LLM_TIMEOUT"}
```

### 前端语音识别建议（零成本方案）

优先使用浏览器 **Web Speech API**（Chrome/Edge 完美支持中文）识别后发 `chat` 文字消息，无需配置后端 ASR。参考实现见测试页。

## 八、RAG 知识库维护（给角色3马新伟）

### 知识文件格式

在 `backend/data/health_knowledge/` 目录下新增 `.md` 或 `.txt` 文件，**头部三行写元信息**：

```markdown
标题：高血压老人日常注意事项
分类：慢病管理
来源：国家卫健委《老年健康核心信息》

（空一行后写正文，按空行分段，段落会自动聚合为约500字的片段）
```

- 分类建议：慢病管理 / 合理用药 / 饮食养生 / 运动保健 / 养生保健
- 来源务必权威（国家卫健委、三甲医院科普、药典），回答时会展示给老人看
- 无头部元信息也能导入（用文件名做标题）

### 导入方式

- **自动**：服务启动时若知识库为空会自动导入一次
- **手动**：改完知识文件后执行（或访问 Swagger 在线执行）

```powershell
# 方式一：接口调用
D:\yinlingban_env\Scripts\python.exe -c "import httpx; print(httpx.post('http://localhost:8000/api/knowledge/import', json={'reset': True}).json())"
```

### 效果验证

```powershell
# 检索测试（看分数与命中内容）
D:\yinlingban_env\Scripts\python.exe -c "import httpx; print(httpx.post('http://localhost:8000/api/knowledge/search', json={'question': '高血压能吃咸菜吗', 'top_k': 3}).json())"
```

### 社区信息维护

编辑 `backend/data/community_info.json`，按现有格式增加条目即可（重启生效）。

```ini
MILVUS_URI=http://milvus:19530
```

后端会自动启用 PostgreSQL / Redis / Milvus（需 `pip install psycopg2-binary redis pymilvus`，Docker 镜像内建议加入 requirements）。

## 十一、常见问题排查（FAQ）

### Q1：启动报"缺少依赖"

```
✗ 缺少以下依赖：fastapi uvicorn ...
```
按提示执行：`D:\yinlingban_env\Scripts\pip.exe install -r requirements.txt`

### Q2：提示 "API Key 无效（401）"

`.env` 中 `DEEPSEEK_API_KEY` 填错了。检查 Key 是否以 `sk-` 开头、有无多余空格/引号。改完重启。

### Q3：提示 "请求太频繁或额度不足（429）"

DeepSeek 调用太频繁或账户余额不足。等一分钟再试；演示前确认账户有余额。

### Q4：端口被占用

```
error: [Errno 10048] ...
```
启动时会自动检测：若 8000 被占（通常是有个旧服务窗口没关），会自动换到 8001 并提示新地址。
想回到 8000：把旧的黑窗口关掉（选中按 Ctrl+C 或直接点×）再启动。

### Q5：启动慢 / 浏览器打不开 localhost（系统代理的坑）

**这台电脑开了系统代理（VPN/加速器），代理会拦截"本机地址"的访问，造成：**
- 请求 DeepSeek 时绕了代理导致连接异常（backend 已默认绕过代理直连外网）
- **浏览器打不开 http://localhost:8000/（转圈、超时）**

解法（任选）：
- 临时关掉代理/切"直连"模式再开测试页
- 或在代理软件里把 `localhost`、`127.0.0.1` 加入"绕过/排除"名单
- 正常双击启动约 **3 秒**就绪；如果明显超过这个数，基本就是代理在捣乱

### Q6：天气查询失败/超时

- 检查电脑能否访问外网（天气源 open-meteo.com）
- 网络慢时可调大 `.env` 中 `WEATHER_TIMEOUT`（默认 8 秒）
- 天气接口完全免费、无需 Key，国内可正常访问

### Q7：WebSocket 连不上

- 确认用 `ws://`（不要写成 `http://`），完整地址 `ws://localhost:8000/ws`
- 连接后必须先发 `{"type":"hello","user_id":1}`，否则会被关闭
- 前端联调遇到跨域问题：本服务已放行所有来源（同源部署无此问题）

### Q8：想重置所有对话/用户数据

停止服务后删除 `backend/yinlingban.db`，重启即全新（知识库在 `data/vector_store.json`，不受影响）。

### Q9：知识库改了没生效

知识导入只在启动时自动执行一次（且仅当库为空）。改完知识文件后手动调 `POST /api/knowledge/import`（body: `{"reset": true}`）。

### Q10：聊天提示"还没配置 DeepSeek API Key"

- 打开 `backend/.env`，把 `DEEPSEEK_API_KEY=` 后面填上自己申请的 Key（sk- 开头）
- 保存后重启 `start.py` 即可
- Key 申请：https://platform.deepseek.com（新用户有免费额度）
- 关键词错误提示对照：401 = Key 无效（检查是否多了空格/抄错）；429 = 请求太频繁或余额不足；402 = 余额不足请充值

### Q11：如何查看当前用的什么模型？

- 启动日志里有
- 访问 `http://localhost:8000/api/model`
- 测试页顶部状态栏直接显示

## 附2：老人分型系统（新增功能说明）

> 详细的大白话说明见 `大白话进度说明.md`，这里只记要点。

### 功能概述

新老人第一次对话时，小伴先主动问**10个问题**：
- 前5题看心态（睡眠/心情/家人/爱好/身体）→ 喂给分型模型
- 后5题记习惯（作息/饮食/家乡口音/急性子慢性子/最近喜事）→ 存档案，聊天时用

判定结果不是单一类型，而是一份**语气配比**（如 孤独68%+焦虑22%+平静10%），
小伴按配比融合多种说话方式——**每个老人一份专属语气配方**。

### 一键蒸馏工具（backend\蒸馏工具\）

```powershell
D:\yinlingban_env\Scripts\python.exe 蒸馏工具\一键蒸馏.py
```

自动完成：导出真实聊天数据 → 合并种子数据（**5254条**）→ 训练（V3架构：TF-IDF贝叶斯+语义信号+转折感知，零依赖）
→ 验证 → 部署到 `蒸馏工具\我的模型\`。**重启后端后自动生效，无需任何配置**。

**训练质量（实测成绩线）**：
- 模板题正确率 100%
- 含蓄表达（"话外音"）单句识别 95%（V2加语义信号前仅57%）
- 边界混淆句（两难题）单句 71%~78%（V3加转折感知后逐步提升）
- **综合判定（真实场景：10题汇总）5/5 全对** —— 单句噪声被多句汇总稀释，上线效果可靠
- 训练/推理一致性自检 100%（无隐蔽bug）

**训练闭环（何时重跑）**：`数据扩充.py` 造数据 → `一键蒸馏.py` 训练 → `严格/二三四五六轮考试.py` 考泛化
→ `回炉X考.py` 错题进训练集（错题本机制）→ 重训。数据越用越准。

可选云端：`一键蒸馏.py --云端 http://服务器/predict`（云端失败自动切回本地）。

### 关键代码

| 文件 | 作用 |
|---|---|
| `app/core/profiler.py` | 分型引擎：10个引导问题、维度打分、语气配比、混合语气生成、蒸馏接入 |
| `app/core/dialogue.py` | 引导流程编排 + 习惯档案拼入聊天上下文 |
| `app/db/models.py` | User 分型字段 + `onboarding_answers` 表（蒸馏训练数据） |
| `蒸馏工具/` | 一键蒸馏、种子数据、验证脚本、模型产物（全中文命名） |

### 分型双引擎

- **规则打分**（兜底）：关键词数分，透明可解释，零成本
- **蒸馏模型**（优先）：发现 `蒸馏工具/我的模型/predict.py` 就自动接管；
  输出五类概率 → 直接当语气配比用；加载失败自动退回规则，服务不中断
